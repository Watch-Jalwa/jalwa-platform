# Browser Social, Recommendations, Live and DRM

## Product boundary

This release is browser/PWA only. It does not introduce Android, iOS, Capacitor, app-store releases or encrypted offline Premium playback. Existing rights-approved non-DRM MP4 downloads remain available. Premium DRM sessions are temporary and online-only.

## Cost-minimized architecture

Jalwa reuses the existing self-hosted PostgreSQL/Supabase, web container, FFmpeg worker, R2 storage and Cloudflare media gateway.

- Social data, moderation queues and notifications live in PostgreSQL.
- Recommendations use PostgreSQL event tables, co-watch relationships and pgvector.
- Semantic vectors use a deterministic multilingual token/trigram model generated by the existing worker/web stack; there is no paid vector database or per-request embedding charge.
- Live channel metadata, schedules, permissions and analytics live in Jalwa. Cloudflare Stream is the initial ingest/transcoding/delivery adapter and can later be replaced by the self-hosted/external adapter.
- DRM packaging uses the pinned Shaka Packager binary in the existing media worker.
- Jalwa proxies Widevine/FairPlay licences only after entitlement and device checks. Plaintext keys and licence payloads are never stored in PostgreSQL or logs.

## Social and community

### Customer features

- comments and two-level replies;
- likes;
- content/category follows;
- share, hide and report actions;
- blocking and muting;
- notifications;
- edit/delete own comments;
- kids-profile commenting prohibition.

### Safety controls

- content-level comments/replies/approval settings;
- configurable slow mode;
- database-enforced blocking and muting;
- report deduplication;
- moderation queue and audit logs;
- staff approve/hide/delete/restore actions;
- no social email fan-out by default.

## Recommendations

Signals include impressions, opens, play starts, completion milestones, likes, saves, shares, hides and reports. Candidate ranking applies:

1. active viewer profile and kids-mode filtering;
2. publication, rights and access eligibility;
3. category affinity;
4. co-watch similarity;
5. semantic similarity;
6. recent popularity and freshness;
7. completion, hide and report penalties;
8. diversity and deterministic experiment assignment.

The daily `Refresh recommendations` workflow calls the protected refresh endpoint. Add `RECOMMENDATION_REFRESH_SECRET` to the GitHub production environment. The self-hosted secret generator now creates it.

## Original live streaming

### Control plane

Studio can create channels, schedule programmes, publish/unpublish, inspect provider status and review viewer telemetry. Channel records store provider IDs and playback URLs only.

### Ingest security

Cloudflare RTMPS/SRT credentials are returned once to the authorized Studio user. Stream keys and SRT passphrases are not stored by Jalwa. Copy them directly into OBS or the broadcaster encoder.

### Playback

- public channels use normal HLS/DASH URLs;
- registered channels require login;
- Premium channels require an active entitlement;
- protected Cloudflare channels receive short-lived signed playback tokens;
- the browser HLS player uses low-latency mode and sends bounded telemetry every 30 seconds.

### Live configuration

GitHub variable:

- `ENABLE_LIVE_STREAMING=true`

GitHub secrets:

- `CLOUDFLARE_STREAM_API_TOKEN`
- `CLOUDFLARE_STREAM_CUSTOMER_CODE`

Keep the flag false until the Stream account is ready. Social and recommendation features do not depend on it.

## Web DRM

### Supported design

- Widevine through `com.widevine.alpha`;
- FairPlay through `com.apple.fps`;
- encrypted CMAF HLS and DASH output;
- HLS browser playback through hls.js EME;
- temporary online sessions only;
- entitlement and browser-device checks before every licence request;
- rate-limited binary licence proxy;
- licence audit metadata without challenge/response payloads.

### Packaging

Studio queues a rights-approved ready source asset. The media worker:

1. downloads the source from private R2;
2. creates 360p, 480p and 720p AVC renditions and optional AAC audio;
3. obtains key material from the configured key/KMS service in memory;
4. invokes pinned Shaka Packager 3.7.2 with `cbcs` encryption;
5. uploads encrypted CMAF HLS/DASH output to private R2;
6. activates a protected playback source;
7. clears temporary files.

The packaging service must return hexadecimal 16-byte `keyId` and `key` values, with optional `iv`, provider reference and protection-system list. The key is not persisted by Jalwa.

### DRM configuration

GitHub variable:

- `ENABLE_WEB_DRM=true`

GitHub secrets:

- `DRM_WIDEVINE_LICENSE_URL`
- `DRM_FAIRPLAY_LICENSE_URL`
- `DRM_FAIRPLAY_CERTIFICATE_URL`
- `DRM_PROVIDER_AUTHORIZATION`
- `DRM_PACKAGING_KEY_URL`
- `DRM_PACKAGING_KEY_AUTHORIZATION`

Keep the flag false until agreements, certificates and provider endpoints are operational.

## Media gateway

The Cloudflare Worker validates a signed token for the requested prefix. For HLS playlists it rewrites every relative playlist, segment and initialization-map URI with the same token, ensuring child requests remain authorized. Explicit origin allow-listing is enabled for Jalwa production domains.

## Deployment order

1. Merge and deploy with both `ENABLE_LIVE_STREAMING` and `ENABLE_WEB_DRM` false.
2. Apply PostgreSQL migrations and run the recommendation refresh.
3. Test social, moderation and recommendation journeys.
4. Add Cloudflare Stream credentials, enable live, deploy and run a private broadcast test.
5. Complete DRM provider agreements and certificate/key-service configuration.
6. Add DRM secrets, enable web DRM and deploy.
7. Package one rights-approved test title and validate Widevine and FairPlay.
8. Run browser, low-bandwidth, entitlement, revoked-device and provider-failure acceptance tests.

## Acceptance requirements

- no comment can bypass kids profile, blocking, slow mode or moderation rules;
- recommendation refresh succeeds and produces behavioural and semantic relationships;
- live ingest credentials do not appear in PostgreSQL or application logs;
- public, registered and Premium live access are correctly separated;
- every protected HLS object request is authorized;
- revoked or over-limit devices cannot obtain DRM licences;
- no DRM key, challenge or response payload is stored or logged;
- provider outages produce customer-safe errors and diagnostic request IDs;
- browser DRM remains online-only;
- all CI and production acceptance workflows pass.
